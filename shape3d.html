How the shapes are built

No database holds these trade shapes, so each stone is generated by functions. A stone is an outline — the girdle seen from above: round, oval, pear, marquise, heart, cushion, octagon, trillion… — crossed with a top and a bottom half, joined by the girdle band.

Half styleWhat it makes
Brilliantcrown: table, stars, bezels, upper girdles · pavilion: lower girdles and mains — the 57 classic facets on a round
Steprows parallel to the outline — baguette, emerald, square; a rectangular pavilion ends in a keel
Single, Frenchsimpler crowns: one facet per main; a table turned 45°
Rosea dome of triangular facets — rose cuts, briolettes, faceted beads
Smooth domecabochons, buff tops, beads, drops
Flattablets and disks, with a small bevel

Every measure is relative to the width (= 1), like gemological proportions: a crown height of 15 % is 0.15 × the width. A shape code is only a recipe — an outline, a cut and a few overrides — so every parameter stays adjustable.

Colour is a first approximation. It comes from the hue given when that hue is a colour, or from the hue the stone implies (Blue Topaz: blue); otherwise the stone is shown in a reference colour. Nothing is assumed for a block left out — as when reading a code, it may be the default or simply not given. A grade 1–4, when given, sets the depth of the colour, and hues such as Milky or White I2 make it hazier. Transparent stones refract and absorb their colour with depth; opaque, milky, pearly and metal ones each have their own material. With light rays on, light is traced through a transparent stone: it refracts in, bounces between the facets — totally reflected where the angle allows — leaves where it can, and is absorbed along the way, so the colour deepens with the path, as in a real cut stone; stones with fire split it into colours.
